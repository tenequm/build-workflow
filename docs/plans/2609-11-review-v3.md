# /review-pr moves onto bernstein, path A: the deep-review shape

Status: DRAFT, awaiting operator build go. Scope: the /review-pr flow only.
Nothing here touches build-plan, build-run, or build-close.

## Goal

/review-pr becomes the same thing upstream bernstein runs on its own pull
requests: one free-text review goal handed to the stock orchestrator in the
target repo's checkout. Bernstein owns spawning, adapters, models, budgets,
receipts. We own only content: the goal text (which carries the five-lens
review doctrine), a seed config naming models, and the eval corpus.
Everything bernstein does for us gets deleted from this repo.

Operator decisions baked in (2026-09-11):

- Stock bernstein only. No custom orchestration, no verification machinery,
  no posting glue, no credential handling beyond bernstein defaults, no
  pond lane, and no upstream PRs or issues - defaults are lived with.
- One free-text goal, not a structured lens task set: it is the fastest
  shape to test and it is literally what upstream does. Structure returns
  only if the corpus number demands it.
- Free models only: opencode Zen (muse-spark-1.3-contributor-free primary;
  deepseek-v4-flash-free and minimax-m3-free available to the goal/judge).
  Fence: free Zen ids train on prompts, so this lane reviews public
  repositories and the eval corpus only.
- Budget $3.00 per run, same as upstream's own deep-review.
- No wrapper recipes. The skill documents the bare invocation; the only
  pre-steps are having the clone and passing our seed.

## The vehicle, verified

Upstream's own usage (.github/workflows/bernstein-pr-review.yml): check out
the repo, fetch the PR diff to a file, then run the orchestrator with a
free-text task and a budget. Locally that is:

    cd ~/pjv/<owner>/<repo>
    gh pr diff <N> > .bernstein-pr.diff
    bernstein -g "<goal text>" --budget 3.00 --headless

with our seed config supplying cli, models and constraints. The installed
bernstein 3.19.1 (pin 0a6bf9f2d6, same as bernstein_operator's lock) is the
engine; no version skew.

Why A over the structured `review --pipeline` path (verified 2026-09-11,
six subagent reports, file:line evidence): the pipeline path's agents are
bare API completions - diff text truncated at 12k chars, 512-token answers,
`adapter`/`prompt_template`/`effort` parsed but never read, no repo access,
no machine-readable output - and its stock template failed on this box on
its own credential name. Path A spawns real CLI agents through the spawner:
repo access for lens archaeology, `role_model_policy` routing with raw
`opencode/<model>` ids passed to `opencode run -m` untouched, budgets
honored, env allowlisted per adapter.

Known stock limitations, accepted: no per-finding blinded verification, no
executed rubrics, no report-witness law, and task dependents release on
self-reported DONE. The judge-reads-findings synthesis inside the run plus
the corpus gate below are the quality mechanism now.

## Steps

### 1. Prove A once

In the bernstein clone (public repo), run the invocation above with our
seed and a first-cut goal against one small open PR. Read the whole output;
record what the run wrote (report file, .sdd artifacts), what it spent, and
which models actually served. Success: a written review report produced by
a stock run on Zen free models.

### 2. Author the content

- `skills/review-pr/templates/review-seed.yaml`: bernstein seed - cli:
  opencode, role_model_policy default on muse-spark at effort high (other
  free ids listed for the manager to use), budget, constraints (never
  commit, never push, write the report to the named file, read the
  validation command only from the base branch), context_files.
- `skills/review-pr/templates/review-goal.md`: the goal text - the five
  lenses' review doctrine distilled from the existing briefs, the report
  format, and the report path. This is where our lens IP lives now.
- SKILL.md: the three-command invocation, the fence, and nothing else.

### 3. Corpus gate

Adapt `fixtures/review-pr-cases/harness.py` to invoke the path-A commands
per case and score the report file against expectations. Corpus cases stay
frozen. Ledger keeps recovered/missed/extras; the first path-A row starts a
new comparability regime and says so. Gate: the corpus must clear before
step 4; the number also decides whether the one-goal shape stands or lens
structure returns via role_model_policy.

### 4. Purge, with the old design preserved

Delete in one commit after step 3 is green:

- `skills/review-pr/scripts/` (the whole custom driver package).
- `fixtures/review-pr/` recording agent and transport fixture.
- `skills/review-pr/templates/stages*.yaml` (all dialects).
- `bernstein_operator/tests/test_review_*.py` for the deleted machinery.
- The acpx path out of /review-pr entirely.

KB cleanup (operator decision: delete outright, no deprecation ceremony;
one artifact record replaces them all):

- Delete these concepts and their index lines: driver-owned-ceremonies,
  per-run-pond-store, cost-is-observability (review scope),
  strict-on-deciding-fields, verification-is-capped-never-batched,
  acpx-model-flag, claude-acp-sessions-need-persistence,
  recorded-agents-hide-brief-defects, review-session-cost-figures,
  provider-errors-end-turns-that-look-clean, a-check-that-cannot-run
  (review scope).
- Add exactly one reference concept: the old driver-owned review design as
  a compact artifact record - what it was, the corpus numbers it reached,
  and that git history holds the code. Nothing else.
- Every concept not named above is untouched.

## Non-goals

- Upstream PRs or issues to bernstein: none, operator decision.
- Posting review results to GitHub: not in scope.
- Any change to build-plan/build-run/build-close and their engine lore.
- Any fork or patch of bernstein.

## Rollback

Steps 1-3 are additive. Step 4 is one revertable commit, taken only after
the corpus gate; git history keeps the old design reachable.
