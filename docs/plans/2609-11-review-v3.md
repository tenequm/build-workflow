# /review-pr moves onto bernstein, path A: the deep-review shape

Status: EXECUTING (2026-09-11). Scope: the /review-pr flow only.
Nothing here touches build-plan, build-run, or build-close.

## Goal

/review-pr becomes the same thing upstream bernstein runs on its own pull
requests: one free-text review goal handed to the stock orchestrator in the
target repo's checkout. Bernstein owns spawning, adapters, models, budgets,
receipts. We own only content: the goal text (which carries the five-lens
review doctrine), a seed config naming models, and the eval corpus.
Everything bernstein does for us gets deleted from this repo.

Operator decisions baked in (2026-09-11, models revised same day):

- Stock bernstein only. No custom orchestration, no verification machinery,
  no posting glue, no credential handling beyond bernstein defaults, no
  pond lane, and no upstream PRs or issues - defaults are lived with.
- One free-text goal, not a structured lens task set: it is the fastest
  shape to test and it is literally what upstream does. Structure returns
  only if the corpus number demands it.
- Model lanes, in preference order:
  - Local-first through pi: the LiteLLM gateway on this box serves
    qwen3.8-27b-nvfp4 (dense, manager candidate), qwen3.6-35b-a3b-nvfp4
    (MoE, ~209 tok/s, lens workhorse) and qwen3.8-flash-next - $0, no rate
    limits, prompts never leave the machine. Seed ids are `litellm/<id>`
    through `cli: pi`; verified limits live in ~/.pi/agent/models.json
    (contextWindow 262144, maxTokens 65536, server-checked).
  - Subscription quality lane: claude-sonnet-5 manager (tool-discipline
    role) with agy gemini-3.7-flash-medium lens workers. Spends quota,
    never dollars.
  - opencode/Zen: OUT of the stack. Free ids share one quota that refuses
    by hanging; entitlements resolve server-side and are undebuggable from
    the CLI; the exported OPENCODE_API_KEY was the harvestable credential
    in the reviewer-reconfigure exposure. Nothing may reintroduce it.
- Fence: public repositories and the eval corpus only, and no model session
  ever receives a GitHub token. Basis: the subscription lanes' data terms
  are account-level, not per-run, and a reviewed tree can still reconfigure
  its reviewer (stock bernstein strips no project-local CLI config; pi's
  own cwd-loading surface is under audit). The local lane removes data
  egress and is the only candidate for ever lifting the fence - after the
  pi audit closes, not before.
- Budget $3.00 per run, same as upstream's own deep-review (a ceiling;
  local and subscription lanes meter $0).
- No wrapper recipes. The skill documents the bare invocation; the only
  pre-steps are having the clone and passing our seed.

## The vehicle, verified

Upstream's own usage (.github/workflows/bernstein-pr-review.yml): check out
the repo at the PR's BASE sha, fetch the diff and PR text to files, then run
the orchestrator with a free-text goal and a budget. Locally, verified on
this box:

    cd ~/pjv/<owner>/<repo>            # BASE commit checked out, detached
    printf '.bernstein-pr.diff\n.bernstein-pr.md\n' >> .git/info/exclude
    gh pr diff <N> > .bernstein-pr.diff
    gh pr view <N> --json title,body --template '...' > .bernstein-pr.md
    bernstein run --seed <seed> --goal "$(cat <goal>)" --budget '$3.00' \
      --auto-approve --quiet --wait 3000 --port <free port>

Hard-won invocation facts (each cost a failed run):

- `--quiet` + `--wait` are what block; `--headless` is a parsed no-op.
- The orchestrator re-parses the seed FILE and requires a `goal:` string;
  the CLI --goal is what runs, the seed goal is a placeholder.
- The task server port defaults to 8052 for every run; two concurrent runs
  crash-loop each other's servers and mint fresh auth tokens until the
  waiter is locked out (the 401 flood). Every run gets its own --port.
- `worktree_setup.copy_files` carries the untracked PR files into agent
  worktrees; without the info/exclude line agents `git add -A` those
  copies and every merge back collides with the parent's untracked
  originals ("would be overwritten by merge").
- A spent or hung model lane does not error: the CLI hangs, bernstein logs
  "agent died without output", and the retrospective blames the merge
  guard. Probe a lane with a one-word prompt before blaming the run.

Why A over the structured `review --pipeline` path (verified 2026-09-11,
six subagent reports, file:line evidence): the pipeline path's agents are
bare API completions - diff text truncated at 12k chars, 512-token answers,
`adapter`/`prompt_template`/`effort` parsed but never read, no repo access,
no machine-readable output - and its stock template failed on this box on
its own credential name. Path A spawns real CLI agents through the spawner:
repo access for lens archaeology, `role_model_policy` routing with raw
model ids (slashes included, `litellm/<id>` for pi) passed to the CLI
untouched, budgets honored, env allowlisted per adapter.

Known stock limitations, accepted: no per-finding blinded verification, no
executed rubrics, no report-witness law, and task dependents release on
self-reported DONE. The judge-reads-findings synthesis inside the run plus
the corpus gate below are the quality mechanism now.

## Steps

### 1. Prove A once - DONE

Proven against bernstein PR #5830 (public repo): 4/4 tasks, 9m32s, $0
metered, review-report.md at the checkout root with a schema-valid findings
block, working tree untouched. Lens 1 caught a real charter-vs-code

workers gemini-3.7-flash-medium.

### 2. Author the content - DONE (committed 0cd48bc, 710e4cd)

- `skills/review-pr/templates/review-seed.yaml`: bernstein seed - lane mix
  per role (final mix decided by the step-3 smokes: pi-local, mixed, or
  subscription), budget, constraints (never commit, never push, write the
  report to the named file, read the validation command only from the base
  branch), worktree copy_files.
- `skills/review-pr/templates/review-goal.md`: the goal text - the five
  lenses' review doctrine, the report format, the report path, the trailing
  machine-readable json block, and the anchor rule (a claim-vs-
  implementation finding anchors at the promise line, never the
  implementation). This is where our lens IP lives now.
- SKILL.md: the three-command invocation, the fence, the info/exclude
  pre-step, and nothing else.

### 3. Corpus gate

`fixtures/review-pr-cases/harness.py` invokes the path-A command per case
(own workspace, own ephemeral port) and scores the report file against the
frozen expectations; a written report is scored even when bernstein exits
nonzero (the exit code is an observation recorded in the note, not the
verdict). Ledger keeps recovered/missed/extras; the first path-A row starts
a new comparability regime and says so. Lane-mix smokes (pi-local 27b+35b,
sonnet+35b mixed, sonnet+gemini) pick the default mix; the full 14-case
gate runs on that mix WITH ledger. Gate: the corpus must clear (bar: the
old design's 13/14) before step 4; the number also decides whether the
one-goal shape stands or lens structure returns via role_model_policy.
