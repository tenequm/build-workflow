## [P1] Preserve pi's reachable SQLite source when `path` is absent

`missing_source_root` only tests the generic `path`, and this branch `continue`s before the adapter is opened. That is not equivalent to "the adapter has no reachable source": `pi-coding-agent` independently reads an optional `sqlite_path`, and its `events_with` deliberately chains `sqlite_events` after the JSONL stream (`packages/pond/src/adapter/pi_coding_agent.rs:463-468`). With `path = "/missing/jsonl"` and a readable, populated `sqlite_path`, a whole-config sync now reports `pi-coding-agent` in `failed_adapters`, exits 0, and never ingests the reachable database; if it is the only adapter, the all-absent shortcut at lines 4119-4165 makes the same mistake before even opening the store. This violates `session-movement-complete` and the PR's central claim that only an unreachable source is skipped. The missing-source decision must account for every source the concrete adapter is configured to read, rather than treating the seam's `path` key as the whole adapter. (`packages/pond/src/main.rs:5237`)

## [P2] Do not classify every duplicate-id drop as benign

The new health verdict omits `IngestSummary::dropped_events` entirely on the assertion that a duplicate is redundant. The validator does not establish that assertion: its duplicate-message floor checks only whether the id was seen (`packages/pond/src/sessions.rs:4277-4289`) and never compares content. For two source records with the same message id but different bodies, the second body is dropped, `drop_reasons.duplicate_message_id` is incremented, but `summary_line()` returns `None` and `degraded_adapters` is omitted. That directly contradicts base rule `adapter-integrity-dedup`, which says equal ids with differing content are not duplicates and must surface as a visible loss, and it makes the fleet gate described in the PR treat actual data loss as healthy. The same omission also covers ordering/session-mismatch drops, which are actionable rather than routine. (`packages/pond/src/main.rs:5261`)

## [P2] Validate adapter names and blobs before the missing-source shortcut

The all-absent fast path treats every resolved config entry with a missing `path` as a valid failed adapter, but `Config::resolve_adapters` only expands the generic path shape; registry lookup and adapter-owned deserialization normally happen later. Consequently `[adapters.codex-clii]` with `enabled = true` and an absent path now exits 0 as a `source_missing` adapter instead of failing as unknown. A known adapter's invalid extra fields are masked too: for example, an absent OpenClaw path plus `skip_kinds = "wrong type"` never reaches `OpenClawConfig` deserialization. The per-adapter shortcut at lines 5237-5250 has the same problem in a mixed run. This contradicts the new spec sentence that malformed config still fails the whole resolve and can cause a typoed adapter to be recorded as successfully handled. (`packages/pond/src/main.rs:4123`)

## [P2] Make the dry-run success message admit the store write

`run_sync_dry_run` calls `open_store` before producing rows, and the edited spec now explicitly acknowledges that opening a new destination creates an empty store. The command nevertheless still finishes with `dry run - nothing written to the store`. On a fresh local or remote destination that is observably false: the dry run materializes storage even though it writes no session data. A user relying on the success line to mean a side-effect-free probe can have the destination changed. The message should make the same narrower claim as the spec. (`packages/pond/src/main.rs:4938`)
