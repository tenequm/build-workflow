## Lens 2: Side-effect gating

### [P2] Propagate adapter validation before opening the store

`packages/pond/src/main.rs:4353` opens the store, which creates a missing local destination at `packages/pond/src/substrate.rs:2052`; with embeddings enabled, `packages/pond/src/main.rs:4377` can also cold-load/download the model. Those side effects are reachable before the new adapter-input gates: the early probes discard every `resolve_sync_adapters` error through `let Ok(...)` at `packages/pond/src/main.rs:4039` and `packages/pond/src/main.rs:4120`, while the error is only propagated when `run_import_stage` resolves again at `packages/pond/src/main.rs:5155` (for example, the empty-path rejection at `packages/pond/src/config.rs:881` or the non-UTF-8 `--path` rejection at `packages/pond/src/main.rs:5849`). Thus `pond sync` with either newly rejected input acquires/writes the lock, creates the store directory, and may download roughly 500 MB before exiting with the validation error; none of those mutations is rolled back. The non-dry-run control flow should return the resolution error before lock/store/model setup, while preserving the promised JSON error shape without executing the stages.
