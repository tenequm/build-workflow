## Angles adopted

1. Dispatch from a dependency DAG, not from the driver's attention (Bernstein).
2. Speculate past the judge: merge on the scripted gate, start dependents,
   judge beside them, fix as a later node. Expressed in the DAG, no new code.
3. Multiple candidates: Flash as a shadow lane, run as its own plan against the
   same base and archived for later blind judging, never in the chain. Out of v1.
4. Plan for decomposability; critique the plan before launch (readiness gate).
5. Verification as a ratchet with evidence: scripted scorer, blind judge that
   must reproduce a defect, judge family never weaker than the executor.
6. The polish tail as non-blocking `polish-N` nodes owned by the phase's files,
   running beside the next phase. AVO's kernel is not adopted; its invariants
   are (gate separate from objective, one item per accepted candidate, every
   rejection a ledger row, supervisor only after the stall detector).

## Tool choices

- Bernstein: deterministic scheduler, YAML plan with conditional edges and
  retry, worktree per task, janitor + gate pipeline, file state under `.sdd/`,
  gates as entry points. Executors and judges run through Bernstein's own
  adapters (`claude`, `codex`, `agy`); they commit on their branch
  (`agent/<session>`), never push, never main. Completion is Bernstein's
  `git-diff` output mode: the agent commits and the process exits.
- Our package owns only what Bernstein does not do: readiness and pins, the
  scorer (gate command, allowlist, report claims), the judge verdict, the
  ledger and `runs.jsonl`, plans, briefs and skills.
- Not adopted: Claude Code dynamic workflows (harness lock), acpx (second
  transport, no agy), pi-workflows (Pi-bound agent nodes), Gas Town (owns
  tmux), Agent Orchestrator (LLM in the loop, desktop app), a herdr adapter
  (below).

## Why native adapters

The first four stages drove executors through herdr panes behind a custom
Bernstein adapter. A spike on 2026-09-02 (`spike-report.md`, run `smoke-native`,
port 8052) measured the native path instead. Six questions:

| # | Measurement | Yes/No | Evidence |
|---|---|---|---|
| 1 | Nested Claude guard blocks a spawned `claude` | NO, it starts | `CLAUDECODE=1` in the driver; `env_isolation._BASE_ALLOWLIST` drops it, spawned claude ran to a committed review |
| 2 | Codex runs high effort + gpt-5.6-sol | YES | session rollout carries `"reasoning_effort":"high"`, `"model":"gpt-5.6-sol"`; the lock is `~/.codex/config.toml`, off-repo |
| 3 | `tests` gate = our gate, per task, in the worktree, pre-merge | PARTLY | cwd, branch, one `gates/<task>.json` per task and the pre-merge refusal are right; `condition: always` skipped and CLAUDE.md was gone |
| 4 | `mock` adapter drives a step to completion | NO | exited in 3.3 s, 0 tokens, wrote nothing; `mock.py` only patches the Bernstein demo repo |
| 5 | Per-step `cli:` dispatches the right adapter | PARTLY | both stages routed, but through `role_model_policy`; the step `cli:` won only the first spawn and was lost on the retry |
| 6 | Judge sees a non-empty `git diff <base>..HEAD` | NO | the merge advanced the integration ref, so base and HEAD both resolved to the same sha and the judge wrote "the diff is empty" |

### What the herdr path cost

Every one of these is in code that existed only to drive a pane, and none of it
survives in the native path.

- Bugs, by class, over stages 1-4: two writers on one decision (Bernstein's
  injected prompt told the agent to self-complete; a judge did, so its task
  passed unjudged); unresolved path, twice (a relative workdir resolved against
  the herdr server's cwd and opened the judge in an unrelated repo; the plan
  root resolved `--git-common-dir` against the process cwd); trusted input (the
  selector's Claude tier names reached `codex --model sonnet` until model and
  effort were locked per adapter class); missing setup (only agy was
  pre-trusted, so codex and claude spawns returned `agent_not_ready`); race (the
  judge started 7 s before the merge and got the repo root); keyword proxy for a
  verdict (the parser counted "certain" over the whole review and blocked a
  `merge as-is`); language assumption (a Go lint cache clean on every repo, "no
  lint result" on linter-less ones); wrong file set (the allowlist check missed
  untracked files and counted orchestrator writes).
- Re-runs and their wall: the gopost 1a replay ran 17m49s to UNHEALTHY with no
  gate row, no merge and no verdict, and the retry was hijacked inside 60 s by
  two orchestrators from the dead run still holding port 8052. The fake-executor
  run 1 died on stale entry-point metadata; a smoke run failed 3/3 because two
  plans in one repo make `load_plan` refuse; one judge spawn was lost to an
  `agent_pane_busy` race and retried; one executor spawn was refused for landing
  at the repo root and burned a retry.
- The completion workaround: `SpawnResult.proc` was the watcher, not the agent,
  so Bernstein's orphan snapshot could rule a live agent dead. The watcher had
  to POST `task complete` and then wait for whichever proof landed first -
  `closed`, three consecutive `done` polls spanning two 3 s ticks, or the
  SIGTERM sent before merging. Settling cost a fixed ~40 s (two 20 s idle polls)
  for a 4 s script.
- Permission stalls: pane agents needed pre-trust, and herdr's dialog guard
  refused a ready codex on any marker word in its output. Native adapters carry
  the flag instead (`claude --permission-mode bypassPermissions`,
  `codex exec --sandbox workspace-write`), so there is no trust step to stall.
- The walkthrough tax: the five skills described panes, workspaces and settling,
  and a driver following them literally hit 12 broken or ambiguous lines.

### The four contradictions the spike found, and their fixes

1. The judge's base ref moves. `git diff <base>..HEAD` with `base` = the
   integration branch is always empty after the direct merge advanced it.
   Fix: `run-config` freezes `git rev-parse <integration branch>` at run start
   and the judge brief diffs that sha (or `HEAD^1..HEAD`).
2. `condition: always` is not always. The built-in `tests` gate returns no
   command when no Python file changed, and the step is reported `skipped`.
   Fix: `command_override: "bernstein-herdr gate"` on the pipeline step, which
   runs verbatim. Bernstein also restores the task CLAUDE.md before the gate, so
   the gate identifies its step from cwd (the agent id) through `team.json` and
   `tasks.jsonl`, never from CLAUDE.md.
3. Per-step `cli:` is not the dispatch key. It won the first spawn and was lost
   on the retry; the durable key is the role, resolved through
   `role_model_policy`. Fix: one role per distinct cli/model (`backend`,
   `backend2`, `reviewer`, `shadow`); step `cli:` stays as documentation.
4. The sidecar brief never reaches the agent. Only the step's `description:`
   does. Fix: the brief goes in the step description, and the judge brief states
   that the reviewer role has Bash, Read, Grep and Glob only, so it commits
   through Bash.

One further limit, not a contradiction: a blocked gate is terminal. There is no
retry, no escalation and no quarantine entry behind it, so the gate itself must
archive the diff and report and write the `runs.jsonl` row on the failing path.

### Two constraints on any target repo

- **One plan per root.** The merge target is the branch checked out at the repo
  root, and `load_plan` refuses a repo holding two plans. A second concurrent
  plan needs its own top-level worktree or clone.
- **A real CLAUDE.md.** Bernstein's worktree isolation refuses a symlinked
  `CLAUDE.md` as pointing into parent-repo mutable state, then falls back
  silently to the main workdir on an agent branch, where nothing can ever merge.
  Readiness fails a symlinked root `CLAUDE.md` or `AGENTS.md` up front.

## Patterns copied from pi-workflows / acpx (contracts, not code)

- effects declare recovery before running: idempotent (relaunch a worktree) vs
  manual (a merge); an uncertain crash parks a manual effect as ambiguous
- claims carry a generation; a stale owner cannot write a run row
- workflow source is content-addressed; resume refuses a changed source
  (brief + spec sections + plan node hashed into the run row)
- step contract with attempt ids; the report is a validated submission
- protected human decisions: only a person answers, model tool cannot
- compose by named exits; re-entry starts with empty state
- progress never routes; a repair loop must show changed evidence or stop
- one status projection; renderers never infer state from rows
- judge children: read-only tools, verified model, no silent fallback

## Judge family rule

Claude reviewing Codex raised pass rate 71.6 -> 89.7; Codex reviewing Claude
dropped it 91.4 -> 82.8 (arXiv 2607.21656, 116 LiveCodeBench tasks). The judge
is Fable or Opus 5 for every arm. Codex and Flash never judge Opus.

## Repo layout in a target project

```
docs/spec.md                     tracked; section numbers frozen; label "DESIGN n" kept in citations
.agents/build/plans/<slug>.yaml  tracked
.agents/build/runs/<run>/        untracked: briefs/, contracts/, readiness/, reports/, judge/, shadow/, runs.jsonl, ledger.md, handoff.md
.sdd/                            Bernstein: runtime/, worktrees/<role>-<id> (one per task), traces/, metrics/
```

Skills take the run directory as an argument; there is no `current` pointer. The
run directory name is not free: `plan.run_dir` is `.agents/build/runs/<plan name>`,
so the plan's `name:`, the plan file name and the run dir slug are one string,
chosen in /build-design.

### Replay checkouts must not share an object store

A replay case is only a measurement if the answer is unreachable from the
checkout the executor runs in. `git worktree add` shares the parent repo's
object store, so every later commit, including the real merged phase, stays
reachable, and the executor can (and did) reproduce the merged commit byte for
byte: the gopost 1a replay on 2026-09-02 produced a tree with an empty
`git diff` against the answer commit, so the run measured nothing about the
executor.

Cut the replay from history instead:

```
git clone --single-branch --no-tags --branch <base-branch> <src> <replay-root>
git -C <replay-root> remote remove origin
```

`--single-branch --no-tags` keeps only that branch's ancestry, and dropping the
remote stops a later fetch from bringing the rest back. Verify with
`git -C <replay-root> log --all --oneline | wc -l` and by confirming the answer
commit is unknown (`git cat-file -e <sha>` fails).

Real builds are unaffected: they run forward from a base that has no answer in
the repo, so a Bernstein worktree over the working repo is the right thing there.
