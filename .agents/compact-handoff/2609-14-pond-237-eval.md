byte-identical diff (168548 B) and body (12413 B). **All nine tasks reached `done`,
zero failed, all seven lens files written - 46 KB - and the report writer could not
deliver them.** Four report-writer attempts died; one burned 1,949,221 input tokens
writing at a filesystem it had no grant for, and a resume attempt died separately on
`Model "gpt-5.6-sol" is ambiguous across providers`.

**Cause: `codex --sandbox workspace-write` grants the worker's own cwd plus a fixed
list of system roots that includes `/tmp` but NOT the checkout root.** The disk guard
added after run 1 moved the checkout off `/tmp` to escape a full filesystem - and in
doing so removed the default grant the report-delivery path silently depended on. One
guard's fix destroyed another guard's unstated precondition. The corpus could not have
caught it: every corpus workspace lives under `/tmp`, where the grant is free, so the
suite had been passing on an accident.

Fixed in `c67d0b8`: both shim builders (harness and SKILL.md) now pass
`-c sandbox_workspace_write.writable_roots=["<checkout>"]`, and a zero-token `codex
sandbox` preflight probe refuses the lane when the grant does not work. Five probes
pass - grant on /home, grant removed (refused), probe from repo root (confirmed
vacuous, so the probe must run from a SUBDIRECTORY), harness probe normal, harness
probe with grant stripped (refused). Two flag-position facts, both verified against
codex-cli 0.154.0: `codex exec` honours `-c` overrides placed BEFORE the subcommand
(the shim's position); `codex sandbox` honours them ONLY AFTER it. A mistyped config
key fails closed. Evidence at `docs/evals/2609-14-pond-237/run-2-undelivered/`; the
durable lesson is in
[the sandbox-grant finding](../../docs/knowledge/findings/a-sandbox-default-grant-makes-location-load-bearing.md).

### Three fixes landed, and one of them was wrong first

- **Disk is a precondition, not a hope.** Both the invocation and the harness
  refuse below 10 GB, scaled by concurrency in the harness.
- **The guard must check `/tmp`, not just the workspace.** `TMPDIR` does not
  reach a worker: a sandboxed agent gets a hardcoded `TMPDIR=/tmp`. The first
  version of this guard read the wrong filesystem and would have passed run 1's
  failure without comment. Confirmed in bernstein's sandbox env builder and by
  measuring where run 2's findings directory actually landed.
- **`report-writer` depends on the five numbered lenses only.** A `-shadow` task
  may never appear in `depends_on`.
- **`disk_exhausted()` sits beside `lane_down()`** so a starved run scores ERROR,
  never MISSED - a host outage must not enter the ledger as a model failure.
