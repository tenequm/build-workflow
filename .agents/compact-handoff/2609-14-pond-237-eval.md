## Facts that cost time to learn

- **Codex effort is not a flag.** `codex exec` reads `model_reasoning_effort` from
  `~/.codex/config.toml`, which on this host already holds `model = "gpt-5.6-sol"` and
  `model_reasoning_effort = "high"`. The bernstein codex adapter having no effort code is
  by design. This repo's own readiness check documents it at
  `bernstein_herdr/src/bernstein_herdr/ready.py:222-232` and hard-fails a run without it.
- **The PATH shims cover `pi` and `claude` only.** `codex` and `agy` are unshimmed and read
  the reviewed tree's own config (`.codex/`, `.agy/`, AGENTS.md). pond is the operator's
  repo, so this lane is safe here and **not** reusable on a third-party repository until a
  codex shim exists.
- **The local gateway has three models, all 262k context**: `qwen3.8-flash-next` 209 tok/s
  (the fastest available - there is nothing quicker to switch to), `qwen3.8-27b-nvfp4`
  78 tok/s (dense, stronger per token), `qwen3.6-35b-a3b-nvfp4` 54 tok/s. Never read or
  print the API key in `~/.pi/agent/models.json`.
- **19 role names exist** (`analyst`, `architect`, `data`, `docs`, `qa`, `retrieval`,
  `security`, `reviewer`, `manager`, ...); `bernstein.core.plan_schema.KNOWN_ROLES` is the
  list.
- **Do not raise `--jobs` past 2** on the local lane.
- Residual defect, not fixed: the engine cannot see a pi agent's liveness, so it judges
  working agents dead. Four to seven tasks fail and retry per run. Costs wall clock, not
  the deliverable. Do not treat "zero failed tasks" as a pass bar.
- A run ends only at a `/proc` cwd sweep: `harness.sweep(pathlib.Path(dir))`.
- Launch long runs `setsid`-detached; the harness's background-task supervisor kills them
  when the host hits a transient low-memory spike (pond indexing has sat at 7 GB RSS).
